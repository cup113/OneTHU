# 分叉 0.11.4-1 发布记录：基线换到上游 0.11.4，macOS 构建机容量绕行

> 最后更新：2026-10-27 01:58

日期：2026-10-27。基线：`main` / `253a851a`（`fork-0.11.4-1` tag 指向该提交）。
本版是分叉首次基于上游 0.11.4 的发布，也是 27→8 历史压缩后的首次发版。

## 1. 本版内容

- 上游 0.11.4：liquid glass 界面打磨、OH 应用服务、统一 CLI 运行时与学习相关更新。
- 分叉保留：独立打包标识与更新源、托盘/悬浮球保活、系统日历差异同步
  （0.11.3-4..-7 的修复链）、自定义日程重复规则。
- 分叉版本记录改为 `0.11.4-1`（`apps/desktop/src-tauri/tauri.fork.conf.json`），
  Android versionCode 跟随上游 11013。

## 2. 发布过程

共四次 dispatch，前三次都卡在 macOS 构建机：

1. 三次 `macos-latest`（macOS 26 arm64）都在排队约 15 分钟后被取消，注解为
   `The job was not acquired by Runner of type hosted even after multiple attempts`，
   并提示 macOS arm64 容量受限；Windows 与 Android 均已成功，`publish` 因缺少
   macOS 产物被跳过。
2. 绕行一：workflow 新增 `macos_runner` 输入（默认空 = `macos-latest`），
   desktop job 按它选择 `runs-on`；macOS 矩阵项补 `rustup target add
   aarch64-apple-darwin`，保证交叉编译仍产出 aarch64 DMG。
3. 绕行二：`macos-15-intel`（x64）能立即拿到 Runner，但 `build-cli-runtime.mjs`
   的架构守卫拒绝在 x64 上打包 arm64 的 CLI 运行时。改为只禁止跨 OS；同 OS
   跨架构时不再打包宿主二进制，走脚本已有的官方 Node 归档下载与 sha256 校验分支。
4. 第四次 dispatch（run `40366657900`，head `253a851a`）三端构建成功，
   `publish` 生成 Release 与 `latest.json`，`Verify manifest resolves` 通过。

发布后发现 `latest.json` 的说明仍是 0.11.3-7 的文案（该文本硬编码在 workflow 里）。
workflow 的清单说明改为本版内容，并手工替换 Release 里的 `latest.json` 资产；
版本号、三端 sha256 与 `releasedAt` 未改动。

- run `40366657900` 结论 success；`publish` 的 `Verify manifest resolves` 通过。

## 5. 已知边界

- macOS DMG 由 x64 构建机交叉打包（rustup target `aarch64-apple-darwin`），
  未在 Apple Silicon 真机安装验证；arm64 Runner 容量恢复后 `macos_runner` 留空
  即回到原生构建。
- `latest.json` 的说明在发布后修正，GitHub 的 `releases/latest/download/latest.json`
  可能短暂返回旧清单（CDN 缓存）。
- Windows 安装包与 Android APK 的签名方式与 0.11.3-7 相同；分叉包的图片资源、
  更新源与包名均未变。
- 分叉与上游共用本地账户名 `OneTHU`，两个包同时开启系统日历同步会互相认领，
  建议只保留一个包开启。
