# 学习会话 403：重试无效，硬刷新才恢复

日期：2026-10-30。用户报告网络学堂课程列表偶发获取失败，界面给出疑似 403 的错误码与「重试」按钮；点重试不恢复，点界面上的硬刷新按钮（整页重载）才恢复；发生时机都不在刚打开 OneTHU 的一小时内。

## 日志取证

本机 `%APPDATA%\app.onethu.desktop.fork\logs\onethu-debug.log`（2026-10-24 至 10-30）中同一形态共 15 次，均为 `PAGE-ERR LEARN HTTP 403`：

> 2026-10-30T13:28:06.733Z | PAGE-ERR LEARN HTTP 403\nHTTP type=html status=200 len=7209

同一时刻的配套证据：

- 失败请求是学习域学期接口 `.../b/kc/zhjw_v_code_xnxq/getCurrentAndNextSemester`，网关回 403：

  > [NATIVE-HOP0] 403 43ms GET https://webvpn.../b/kc/zhjw_v_code_xnxq/getCurrentAndNextSemester

- 并发中的 info / card 请求走同一张 wengine 票，状态 200；失效的是学习域自己那份会话，不是网关票。
- 同一端点在会话重建成功后立即回到 200；失败窗口内的每次重试仍是 403（10-24 05:24:22、05:24:29、05:24:31 连续三次；10-27 13:27:29、13:27:32）。
- 每次报告后 2 至 9 秒都出现整页重载（`PROBE js-modules-evaluated`），即硬刷新按钮；10-30 13:28、10-27 09:16、10:16、11:01 四例都是先 403、后重载。
- 重载之后 `LEARN-SILENT 路径零 hook=ok 凭据=ok`，会话由 lib 探活加 learn 漫游重建，随后同一接口 200。
- 10-30 13:28:06 的 `SOFT-RECOVER[global] ok (77ms)` 说明主会话当时完好：后台自愈链救的是网关票，与学习域那份会话是两件事。

结论：403 是学习域对「无会话或陈旧 `_csrf`」的答复。客户端把它当作普通错误上抛（`Error("HTTP 403")`），既不重登也不作废旧凭据，所以「重试」拿同一份死会话与旧 `_csrf` 重放，结果仍是 403；硬刷新会生成新客户端（`_csrf` 为空），走建立链重新取证才恢复。

## 修复

`packages/core/src/learn/client.ts`：

- 读接口的 401 与 403 统一按会话失效处理：`#readText` 作废 `#csrf` 并抛 `SessionExpiredError`，交给既有 `#withRelogin` 静默重建一次并重放原请求。
- 取凭据页（`#fetchCsrf`）遇到 403 时按「这一轮没有凭据」返回 `null`，让 `#establishSession` 走重建链；`resume()` 因此能原地自愈。
- 重建后的请求使用新 `_csrf`：`silentRelogin` 重建会话后重新抓取凭据，重放必然带新值。

不改动写路径：提交作业走 `postForm`，403 时仍按 HTML 响应体判定（登录页才重登，服务器错误页如实报错），不会被自动重放成重复提交。非会话状态码（5xx）不触发重登，也不丢凭据。

## 验证

- 新增 `tools/learn-session-recovery-test.mjs`，接入 `pnpm run test:login`。四组断言：403 后重建一次并用新凭据重放；重建失败时抛会话错误且旧凭据作废、下一次重试可重新建链；取凭据页 403 时 `resume()` 自愈；500 不误判为掉线。
- 反证：把 `packages/core/src/learn/client.ts` 退回修复前（字节级还原后校验 SHA-256 一致），第 1 组即以 `Error: HTTP 403` 失败，栈显示该错误从 `#readText` 穿出 `#withRelogin` 直达调用方，与日志中的行为一致。
- `@onethu/core`、`@onethu/desktop` TypeScript 检查通过；`@onethu/core` 既有 smoke 测试全部通过。

## 边界

- 学校若以 403 表达「这条路径无权限」（此前实测的拒绝页是 200 加可见文案），现在会先尝试一次静默重建，再以会话错误呈现；重建不会改变权限判定，代价是一次多余的重建。
- 静默重建依赖宿主注入的 `reloginHook`（lib 探活加 learn 漫游）；重建本身失败时，界面仍落到原错误条，此时再点「重试」会重新建链，不再复用死会话。
