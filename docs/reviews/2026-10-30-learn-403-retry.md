# 学习会话 403：重试无效，硬刷新才恢复

日期：2026-10-30（2026-10-31 复审修正）。用户报告网络学堂课程列表偶发获取失败，界面给出疑似 403 的错误码与「重试」按钮；点重试不恢复，点界面上的硬刷新按钮（整页重载）才恢复；发生时机都不在刚打开 OneTHU 的一小时内。

## 日志取证

本机 `%APPDATA%\app.onethu.desktop.fork\logs\onethu-debug.log`（2026-10-24 至 10-30）中同一形态共 15 次，均为 `PAGE-ERR LEARN HTTP 403`：

> 2026-10-30T13:28:06.733Z | PAGE-ERR LEARN HTTP 403\nHTTP type=html status=200 len=7209

同一时刻的配套证据：

- 失败请求是学习域学期接口 `.../b/kc/zhjw_v_code_xnxq/getCurrentAndNextSemester`，网关回 403：

  > [NATIVE-HOP0] 403 43ms GET https://webvpn.../b/kc/zhjw_v_code_xnxq/getCurrentAndNextSemester

- 并发中的 info / card 请求走同一张 wengine 票，状态 200；失效的是学习域自己那份会话，不是网关票。
- 同一端点在会话重建成功后立即回到 200；失败窗口内的每次重试仍是 403（10-24 05:24:22、05:24:29、05:24:31 连续三次；10-27 13:27:29、13:27:32）。
- 每次报告后 2 至 9 秒都出现整页重载（`PROBE js-modules-evaluated`），即硬刷新按钮；10-30 13:28、10-27 09:16、10:16、11:01 四例都是先 403、后重载。
- 重载之后 `LEARN-SILENT 路径零 hook=ok 凭据=ok`，会话由 lib 探活加 learn 漫游重建，随后同一接口 200。
- 10-30 13:28:06 的 `SOFT-RECOVER[global] ok (77ms)` 说明主会话当时完好：后台自愈链救的是网关票，与学习域那份会话是两件事。

## 根因

学习域的 403 是「这一轮的学习会话不被承认」（无会话或陈旧 `_csrf`）。客户端只把 401 当会话失效，403 是一个裸 `Error("HTTP 403")` 直接上抛；`#withRelogin` 只捕获 `SessionExpiredError`，因此既不重登、也不作废旧凭据。界面「重试」拿同一份死会话与旧 `_csrf` 重放，结果固定是 403；硬刷新生成新客户端（`_csrf` 为空）走建立链重新取证才恢复。

## 修复

| 位置 | 改动 |
|---|---|
| `core/learn/client.ts#readText` | 401 与 403 都抛 `SessionExpiredError`，交给既有 `#withRelogin` 单飞重建一次、用新凭据重放；**不清** `#csrf` |
| `tools/learn-session-recovery-test.mjs`（新） | 5 组离线断言，接入 `pnpm run test:login` |
| `tools/learn-response-recovery-test.mjs` | 原「403 保留权限失败」断言改为新契约：401/403 各重建一次，429/503 仍是服务错误 |
| `docs/reviews/2026-10-30-learn-403-retry.md`（新） | 取证、推导与边界 |

取凭据页（`#fetchCsrf`，含启动探活）**不**改动：那一步没有可重放的读请求，宿主按「探活失败」处理，由启动链的静默重登兜底。

写路径不变：提交作业走 `postForm`，403 仍按响应体判定（登录页才重登，服务器错误页如实报错），不会被自动重放成重复提交。

## 复审修正（2026-10-31）

### 并发里晚到的 403 不得作废刚重建好的凭据

初版在 `#readText` 里直接把 `#csrf` 清空。并发扇出（每门课三种作业、通知、文件同时发）时，先到的 403 触发重建并装上新凭据；另一条**在重建之前就发出**的请求晚到回 403，把新凭据清成 null。`#withRelogin` 的 `generation !== this.#sessionGeneration ? Boolean(this.#csrf)` 快路径因此判成「这一代重建失败」，该请求收到假会话失效，下一次读取还要多付一轮重建。

修正：`#readText` 只抛标记；作废由 `#recoverSession` 在单飞锁内完成，那里才是「当前这一代」的边界。回归用例见测试第 3 组：两个并发读同时用旧凭据，A 先自愈，B 的晚到 403 必须用新凭据重试成功，新凭据保留，整轮只重建一次。

### 取凭据页的 403 保持服务失败

初版把 403 也并进 `#fetchCsrf` 的「这一轮没有凭据」。启动探活 `probeLearnSession` 与启动守卫依赖的正是「探活失败 → 启动链静默重登」（`tools/learn-recovery-probe-test.mjs` 第 4 组：403 必须拒绝且只发一次请求）。已撤回，`#fetchCsrf` 只认 401。

### 403 在读接口上的语义

既有守卫 `tools/learn-response-recovery-test.mjs` 原有一条「403 保留权限失败」。该断言来自 2026-10-22 的设计假设：同一提交（`b9fe62f3`）里的 403 实证是 Seafile 壁纸权限（`HTTP 403: You do not have permission to access this file`），learn 侧没有真实 403 样本，夹具是手写串 `'Denied'` / `'Access denied'`。

本机日志（2026-10-24 至 10-30）388 条 403 的落点：

| 落点 | 次数 |
|---|---|
| learn `b/kc/zhjw_v_code_xnxq/getCurrentAndNextSemester` | 363 |
| info `b/info/xxfb_fg/xnzx/template/more` | 25 |
| 其他 learn 端点 | 0 |

15 个 episode 均伴随 learn 桶丢掉 `JSESSIONID`，重建后同一请求立即 200；真实「无权限」的形态是 200 加「您没有执行当前操作权限」壳页（`classifyLearnPage` 的 `learn-denied`）。因此读接口上的 403 与 401 同处理，既有断言改为新契约。

未采用「按响应体区分」：`LEARN_DENIED_RE` 含 `forbidden`，网关的通用 `403 Forbidden` 页会被判成无权限而压掉自愈——正是本次要修的故障形态。

## 验证

- `tools/learn-session-recovery-test.mjs` 5 组：403 重建一次并用新凭据重放；重建失败抛会话错误且旧凭据作废、下一次重试可重新建链；并发晚到 403 不作废新凭据；取凭据页 403 仍上抛且只打一次；500 不误判为掉线。
- 反证：把 `#readText` 的 403 分支注入回 401-only（字节级还原后校验 SHA-256 一致），第 1 组即以 `Error: HTTP 403` 失败，栈显示该错误从 `#readText` 穿出 `#withRelogin` 直达调用方。
- `tools/learn-response-recovery-test.mjs` 30 例通过；`tools/learn-recovery-probe-test.mjs` 5/5 通过（需 tsx，沙箱内 esbuild 无法 spawn，单次提权执行）。
- `pnpm run test:login` 全绿；`@onethu/core`、`@onethu/desktop` TypeScript 检查通过。

## 边界

- 若学校用 403 表达「这条路径无权限」，读接口会先做一次静默重建，再以会话错误呈现；实测拒绝页是 200 加可见文案，代价是一次多余的重建。
- 启动探活上的 403 不走这条自愈，仍由启动链静默重登兜底。
- 静默重建依赖宿主注入的 `reloginHook`（lib 探活加 learn 漫游）；重建本身失败时界面落到原错误条，此时再点「重试」会重新建链，不复用死会话。
- 生效需要重新构建桌面端。
