# 分叉 0.11.4-4 发布记录：网络学堂的失败归因

> 最后更新：2026-10-29 08:30

日期：2026-10-29。产物构建自 `814a7899`（`fork-0.11.4-4` tag 指向该提交），Release 建于
2026-10-29 00:22（+08）。基线仍是上游 0.11.4-fix-1；本版主体是 0.11.4-3 之后进入主线的两处
网络学堂修复，外加一处让跨架构 macOS 包能通过校验的构建脚本修复。

## 1. 本版内容

- **附件失败归因不再挪用登录墙**（`0661fc26`）。通知附件地址末段为空、请求恒 404，而旧代码
  不看 `resp.status`，又把「非图片 HTML」一律当登录墙，于是把「文件已不在」报成「登录状态已
  失效」。现在 `lib/loginWall.ts` 把 login / gateway / html 三分，只有前两类算登录墙；预览取数
  先判 `resp.ok`，非 2xx 如实报 HTTP 状态。`isDownloadableAttachmentUrl` 在解析层拦掉没有
  文件名的地址，通知附件只扫附件区块，附件卡只在真有可下载地址时出现（.html 附件因此可以预览）。
- **提交页被拒不再让作业详情整页报错**（`c91207f3`）。已批阅或已过提交期的作业，`tijiao` 恒回
  wengine 的「您没有执行当前操作的权限」壳页，`classifyLearnPage` 把它误判成 webvpn 引导页，
  双页合并随即整体失败。新增 `learn-denied` 分类（短页且渲染了拒绝文案），`wengineInterstitial`
  要求可见文字为空；`#homeworkPageDetail` 只对「提交页被拒」降级为 `hasSubmitForm=false`，
  正文与四类附件照常渲染，传输层故障仍按可重试的失败上报。
- **跨架构构建校验**（`814a7899`）。`bundled-cli-startup-test` 原来断言
  `manifest.arch === process.arch`，x64 macOS 交叉打包 aarch64 时必红。现在平台仍须与宿主一致，
  架构不一致时校验全部文件与 `node.gz` 的 sha256、跳过启动（x64 宿主跑不了 arm64 的 Node）。
- 护栏：新增 `tools/learn-attachment-url-test.mjs`、`tools/file-preview-wall-test.mjs`，扩容
  `learn-resource-enumeration` / `http-wengine-bootstrap`，并把前两者接进 release workflow 的
  「学习会话」检查组。

## 4. 验收

- run `40722494233` 的 guard / android / windows / macOS / publish 全部 success；
  publish 的 `Verify manifest resolves` 通过。
- 下载 Release 的 `latest.json`：`version=0.11.4-4`，三端 size/sha256 与 GitHub 资产 digest
  一致，`notes` 为本版内容（清单说明随版本在 `release.yml` 里改过）。清单的 `releasedAt` 是
  UTC 日期 `2026-10-28`，对应本地 10-29 00:22 的发布时刻。
- `fork-0.11.4-4` tag 指向 `814a7899`，Release 非 draft、非 prerelease。
- 提交前本地护栏：`learn-attachment-url`、`file-preview-wall`、`http-wengine-bootstrap`、
  `learn-resource-enumeration`、`fork-build`、`release-manifest`、`update-version-order` 全过。
- 跨架构分支自证：把本地 `runtime.json` 的 `arch` 改成 `arm64` 后输出
  `files and Node checksums verified (cross-build on win32/x64; startup not run)`；再把
  `dist/sdk/policy.mjs` 改坏，断言报该文件 sha256 不符——完整性校验没有被整段跳过。

## 5. 已知边界

- macOS DMG 由 x64 构建机交叉打包（`rustup target aarch64-apple-darwin`）。本轮的跨架构路径
  只校验了包内文件哈希：打包进去的 arm64 Node 与 CLI 运行时没有被真正启动过，也没有在
  Apple Silicon 真机安装验证。原生 `macos-latest` 容量恢复后 `macos_runner` 留空即回到原生构建。
- 交叉编译比原生慢：本轮 macOS job 16 分 27 秒（16:05:45 → 16:22:12），是整条 run 的瓶颈。
- `pnpm guard` 里的 `docs-prose-lint`（4 处）与 `ui-copy-lint`（12 处）在发版基线 `4c6c3ecd`
  上已是红的存量问题，不在 release workflow 的检查面内，本版未处理。

## 6. 回退

- 撤销发布：`gh release delete fork-0.11.4-4 --cleanup-tag`；已装 0.11.4-4 的客户端拿不到
  清单，需回装 0.11.4-3。
- 代码回退点：`4c6c3ecd`（本版发版前的主线）。
