# 分叉 0.11.4-2 发布记录：Windows 本机 CLI 服务起不来的修复

> 最后更新：2026-10-27 15:55

日期：2026-10-27。基线：`main` / `f3725ed7`（`fork-0.11.4-2` tag 指向该提交）。

## 1. 本版修的故障

现象：Windows 上登录恒失败，界面提示「本机服务未就绪。请更新 OneTHU 并重新启动，或重试连接。」；
诊断摘要的「最近报错」在 `CLI_DAEMON_START_FAILED`、`CLI_DAEMON_PRIVATE_FILE_REQUIRED`、
`Session recovery is still in progress.` 之间跳；卸载重装无效；同一版本 Android 正常
（移动端不走常驻 CLI 服务，`usesSharedRuntime()` 为 false）。

三个独立成因，任一都足以挡住登录：

1. **`privateMode()` 用 PowerShell 写私有 ACL**（`packages/sdk/src/node/storage.ts`）。
   两条路径都会让 daemon 在初始化阶段以 `AUTH_STORAGE_ACL_FAILED` 退出，而 GUI 只会把它显示成
   「本机服务未就绪」：
   - 目录的安全描述符曾被**提权进程**写过之后（本次是「以管理员身份启动」那一轮），非提权进程再
     `Set-Acl` 会报 `PrivilegeNotHeld(SeSecurityPrivilege)`。实机对照：旧 profile 及其 `im`
     子目录都失败，同一台机器上新建目录成功。
   - 从 PowerShell 7 终端启动时，node 派生的 Windows PowerShell 5.1 继承 PS7 的 `PSModulePath`，
     会把 PS7 的 `Microsoft.PowerShell.Security` 加载进 5.1，`Set-Acl` 根本不存在
     （`CouldNotAutoloadMatchingModule`）。去掉该变量即恢复。

   改为 `icacls /inheritance:r /grant:r *<SID>:F`：只写 DACL，不需要 `SeSecurityPrivilege`，
   也不依赖 PowerShell 的模块解析；与同包 `notifications/storage.mjs` 早已采用的写法一致。

2. **凭据文件属主检查过严**（`apps/desktop/src-tauri/src/cli_daemon.rs` 的 `windows_private_acl()`）。
   它要求属主等于当前用户，而 Windows 给提权进程新建的对象默认属主是 `BUILTIN\Administrators`，
   于是管理员那一轮写出的 `daemon-access.json` 永远被拒（`CLI_DAEMON_PRIVATE_FILE_REQUIRED`），
   而且该文件存在期间普通启动也会被同一个检查拦住。改为接受「当前用户或该内建组」，DACL 判定不变：
   决定谁可以打开这个发现文件的是 DACL，属主只是启发式。

3. **日历同步轨迹的诊断权限从未生成**（`plugins/onethu-calendar`）。`build.rs` 的命令列表漏了
   `sync_trace`，于是 `default.toml` 里也没有 `allow-sync-trace`，诊断摘要的「日历同步」行恒为
   `Command plugin:onethu-calendar|sync_trace not allowed by ACL`。与登录无关，同一次修掉。

## 4. 验收

- 发布后重新下载 Release 的 `latest.json`：`version=0.11.4-2`，三端 size/sha256 与资产一致；
  `notes` 已是本版内容（0.11.4-1 曾把上一版文案写进清单，这次随版本一起改）。
- `fork-0.11.4-2` tag 指向 `f3725ed7`，Release 非 draft、非 prerelease。
- 产物内证：`resources/cli-runtime/dist/sdk/index.mjs` 含 `icacls` 与 `/inheritance:r`，
  不含 `Set-Acl` —— 修的是真正进包的那份运行时。
- 静态校验：`tsc -p packages/sdk/tsconfig.json --noEmit`、`cargo check`（应用与
  `tauri-plugin-onethu-calendar`）均通过；后者的构建脚本重新生成的
  `permissions/autogenerated/{reference.md,schemas/schema.json}` 与手写内容一致。

## 5. 已知边界

- profile 仍是用户级 `%LOCALAPPDATA%\OneTHU CLI`；本版起不需要管理员权限，也**不应再以管理员启动**。
- 本机仍留有上一版排查时的 `%LOCALAPPDATA%\OneTHU CLI.bak-20261027`，可直接删除。
- macOS 由 `macos-latest`（arm64）原生构建，未在 Apple Silicon 真机安装验证。
- 常驻 CLI 服务只在 Windows/macOS 存在；Android 仍是进程内宿主，因此本故障与 Android 无关。
- `apps/desktop/src-tauri/gen/schemas/{android,macOS}-schema.json` 要等对应平台的构建才会带上
  `allow-sync-trace`；Windows/desktop 两份已随本版更新。
