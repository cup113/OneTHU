## 1. 本版内容

- **提交作业可拖入附件，Windows 上缺的拖放一起补回**（`55ccc6a1`）。往提交卡拖文件毫无反应
  是两层原因叠在一起：窗口层 Tauri 默认 `dragDropEnabled: true`，wry 在 WebView2 外层接管
  文件并改发 `tauri://drag-drop`，网页 `drop` 拿不到 `dataTransfer.files`；页面层提交卡只有
  一个裸 `file input`，没有任何接收区。现在主窗口关掉原生拖放，接收区（`lib/fileDropZone.ts`）
  以 capture 注册并 `stopPropagation` 收口，落点并入既有 `setSubFile`（与「选择文件」同一条
  路），悬停时才出虚线框与「松开即可添加附件」。同一行改动让暂存箱的文件拖入与雨课堂作答
  编辑器的拖图上传在 Windows 上一起恢复——它们此前失效是同一个根因。
- **会话自愈的判定、证明与闸门重做，教务域独立自愈**（`24498fcc`）。网关 cookie 端点改封闭
  世界分类（拿到 XSRF-TOKEN 算活、登录页/壳页算死、其余算未知），空响应不再直接判死而是先
  预热应用入口再问；重登是否生效改由门户探针回答，避免「网关票活着、门户已死」时把无效重登
  记成有效；连续三次确认死亡才熔断，结论不明只进退避，`libEnsureSession` 单飞。教务域在
  JSONP 撞上登录/超时页时就地重新漫游一次再重试，今日课程有旧数据时也显示错误条。
- 清单说明改为本版内容（`8d3a8b2d`）。`release.yml` 里把 `--notes` 收成 shell 变量再传参，
  才能保留段落；正文仍避开英文双引号与反引号（走 bash 双引号传参）。
- 护栏：新增 `tools/learn-file-drop-test.mjs`（含反向对照：去掉 capture、绕开 `setSubFile`、
  配置写 `true` 都必须红）；拖入的窗口前提写进 `docs/homework.md §3.1`。

## 5. 已知边界

- **macOS 包是 x64 构建机交叉编译**（`macos-15-intel` + `rustup target aarch64-apple-darwin`），
  与 0.11.4-4 同一路径。打包进去的 arm64 Node 与 CLI 运行时只校验了文件哈希，没有在 Apple
  Silicon 真机安装验证；`macos-latest` 容量恢复后 `macos_runner` 留空即回到原生构建。
- **本版 CLI 的 macOS 包是 `darwin_x64`**（跟构建机走），与 0.11.4-6 的原生 `darwin_arm64`
  不同。Apple Silicon 上「安装 CLI」拿到的是 x64 运行时。
- Windows 安装包仍为未签名 NSIS；SmartScreen 会拦首次运行。
- Android 包沿用既有签名材料与默认 NDK（28.2.13676358），只经构建，未在真机走完整链路。
- 拖入附件只在 Windows dev 壳上验过；macOS/Android 两个平台的拖放路径（Android 无此交互）
  未单独验证。
- `pnpm guard` 里的 `ui-copy-lint`（12 处）与 `docs-prose-lint`（4 处）是存量红灯，不在
  release workflow 的检查面内，本版未处理。
