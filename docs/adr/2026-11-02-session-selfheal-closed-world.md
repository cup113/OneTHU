# 会话自愈：探针封闭世界判定 + 重登有效性证明

状态：已实现。护栏 `tools/session-probe-policy-test.mjs`、`tools/login-public-key-test.mjs`、`tools/zhjw-roam-retry-test.mjs`。

## 问题

2026-11-02 08:11–08:57 实录：info 会话死亡后，热上下文 46 分钟无法自愈，只有重启能救。网关 cookie 端点回 `200 + 空 body`（连续五次），旧判定把它归入「未知失败」，而提交凭据的闸门只认「正面死亡证据」，于是 learn 重登钩子、InfoClient renewer、`softRecover`、十分钟保活全部静默；唯一能救的完整登录只接在启动链上。

历次修复都在给白名单追加一种新的死亡形状（会话旗标、考试 JSONP、webvpn 引导页、learn 403、门户错误 JSON），而学校的死亡形状是开放集：每修一次只是多记一具尸体。

## 决定

### 判定

网关 cookie 端点是基础设施探针，没有业务页形态，响应空间大体可穷举：拿到 `XSRF-TOKEN` 算活；登录页、WebVPN 壳页算死；其余非空形状算未知。空 body 不直接判死——全新 SSO 会话还没访问过 info 时，网关对这个域本来就没有可回的 cookie（SDK 的 identityProbe 早有同款观测）。所以空体先做一次应用入口预热，再问一次；仍然空才判死。

业务页与业务 JSON 维持原规则：只有正面死亡证据才允许重登，未知形状一律不碰凭据。传输失败在分类器之前抛错，永不触发重登。

### 证明

登录成功不等于服务可用，重登后必须在五秒窗口内被证明。证明用的是**门户探针**（grjbxx 的 ryh），与判定死亡时同一个判据——不是网关票。网关票活着恰恰是门户会话死时的常态，拿它当证明会把无效重登记成有效，退避永不启动。

窗口按墙钟封顶：每次探针都被截到剩余额度内，探针卡死不会把五秒拖成传输层的九十秒。结论取最后一次观测：中间夹着 5xx 的混合窗口算结论不明，不记死。

### 计数

两种失败分开记。门户探针判死记「确认无效」，连续三次开熔断；结论不明（5xx、陌生页面、断网）只进退避、永不熔断——不明并不构成「重放凭据没用」的证据，但反复重放同样没有意义，所以压节奏而不是停手。

退避阶梯按两种失败的合计推进：三十秒起、封顶十分钟。健康的权威探活与只读探针判活都让计数就地衰减，历史抖动不会留在账上凑数。

熔断期间仍做只读探针：探针判活即复位。「误判把自己锁到进程结束」不可接受。人工登录与 2FA 完成都复位。

### 闸门与并发

闸门只有一处：凭据在内存、二十秒冷却已过、退避未生效，三者同时满足才允许走重登链。不存在绕过闸门的旁路——强制重登（选课死结那条）走同一处判断，熔断打开时直接返回失败，不重放账密。

并发入口共享一条恢复链：N 个面板同时失登只跑一次 `libEnsureSession`。没有这道单飞，一次无效重登会被记成 N 次，一个网络抖动就能凑够三次把熔断打开。

## 后果

热路径所有恢复入口继续汇流到 `libEnsureSession`，不新增登录入口。重登成功后串行补域：作废教务一次性漫游旗标、清空静态会话缓存；学习会话由各自的调用方（learn 重登钩子、校园数据重漫游）按需重建，不在补域里重复漫游。

代价是每次重登多一次门户探针，且熔断打开后自动恢复停止、需要用户手动登录。

## 边界

熔断只管应用入口（`libEnsureSession`）。lib 内部的其它漫游包装（GitLab、THOS、程序设计等）直接调 `verifyAndReLogin`，不经过本策略，仍受 lib 自己二十秒闸门约束。把熔断做成全局需要在 lib 层加钩子，超出本次范围。

空体判死的残余风险是「一次多余的密码重放」：若空体来自限流而会话仍可用，证明探针会随即判活并清零，不会累积成熔断。真正的确认实验（活会话 + 强制限流）仍需真机。

## 补记：2026-11-03 教务域独立会话

真机跑了一整天，前半场证明上面的判定与证明都成立：冷启动时空体 → 预热 → 再问仍空 → 判死 → 重登 → 门户探针判活 → 课表出数，整链在一秒内走完。下午暴露了另一件事：门户与学堂全程 200 的同时，教务 `jxmh_out.do` 302 落到 `timeout.jsp`，「本周课程」失败。

失败在界面上看不见——卡片已有旧数据时错误条不渲染，而今日课程一天不变，「没更新」与「更新了」观感相同，这次被忽略了三小时四十分钟。

判定只覆盖一条会话，教务是另一条寿命。对教务死、门户活这种状态，门户探针判活是正确结论，任何以它为条件的恢复都不该动作；但续约者的二十秒到十分钟冷却把「没去试」表达成「试了没用」，调用方据此放弃重试，一次性漫游旗标也不清零，之后每次取数都撞同一个死会话。

所以教务 JSONP 自带一次就地重漫游再重试，不经过续约者、不依赖门户判活、也不要求整条重登。重试只认「落在登录/超时页」这一种证据，重漫游自己失败就如实抛出，不做第二次循环。同时把可见性补上：有旧数据时失败也要出错误条，否则这类失败永远不可见。

2026-11-04 评审又补四处。考试的 `timeout.jsp` 与课表同形，此前被归成「查询窗口太大」的服务端错误，永远进不了重漫游——现在它单独一类，只在教务局部重试里算「可能死」，仍不喂给重登。证明窗口原先按五百毫秒连采样，死会话一次探针要三个请求，一次无效重登能打出近二十个请求，这比它想防的风暴更像风暴；改成最多三次。教务重漫游补了单飞，首页两个入口同时撞死会话时不再各跑一条链。错误条包进单个宿主子节点，否则白板磁贴里它和课表各占一份高度。
